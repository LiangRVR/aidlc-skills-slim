# Requirements - 数独 Web 游戏

## Intent Analysis Summary

- **User Request**: "我想创建一个可以玩数独的web游戏，只有前端，没有后端。前端使用游戏引擎。"
- **Request Type**: New Project (greenfield)
- **Scope Estimate**: Single application（单前端应用）
- **Complexity Estimate**: Simple-to-Moderate
- **Requirements Depth**: Standard

## 需求决策（来自澄清问题）

| 决策项 | 选择 |
|---|---|
| 游戏引擎 | Phaser 3 |
| 开发语言 | TypeScript |
| 构建工具 | Vite + npm |
| 功能范围 | 完整版 |
| 界面语言 | 中文 |

## Functional Requirements

### FR-1 谜题生成
- 随机生成数独谜题，保证有唯一解
- 生成过程在客户端完成，无网络依赖

### FR-2 难度选择
- 提供三档难度：简单 / 中等 / 困难（第三轮 FR-14 扩展为四档，新增"专家"）
- 不同难度对应不同的预填数字数量（挖空数量不同）

### FR-3 数字填写
- 点击选中格子后输入数字
- 支持屏幕数字键盘（点击）和物理键盘（1-9）两种输入方式
- 预填格子（题目给定）不可修改，视觉上与用户填写数字区分

### FR-4 冲突提示
- 输入与同行、同列或同宫已有数字冲突时，立即给出视觉提示（高亮冲突格）

### FR-5 完成判定
- 棋盘填满且全部正确时判定胜利，展示胜利反馈与用时

### FR-6 候选数笔记
- 支持笔记模式（pencil marks）：在格子内标注多个候选数
- 笔记模式与正式填写模式可切换
- 正式填入数字后自动清除同行/列/宫中相同的候选数标注

### FR-7 计时器
- 游戏开始后自动计时并显示
- 胜利后停止计时

### FR-8 提示功能
- 玩家可请求提示，系统自动填入一个正确的空格数字

### FR-9 错误次数限制
- 填入错误数字计入错误次数
- 错误次数达到上限（3 次）判定失败，展示失败反馈

### FR-10 撤销 / 重做
- 支持撤销上一步操作（填数、删数、笔记）与重做

### FR-11 本地存档
- 使用 localStorage 自动保存游戏进度（棋盘状态、难度、用时、错误次数、操作历史）
- 重新打开页面时可选择继续上次游戏或开始新游戏

### FR-12 新游戏 / 重开
- 可随时开始新游戏（选择难度）
- 可重置当前谜题重新开始

### FR-13 连击特效系统（第二轮需求新增）- 填对一个数字时，该格子播放正面反馈特效（粒子爆发等）
- 连击机制：连续填对时特效分档升级，从单格特效逐步扩张到全屏特效
- 完成整行/整列/整宫（9 格全部填对）时，触发该区域的整体特效
- 高档连击伴随棋盘持续氛围特效（如边框脉冲、上升粒子），营造"热场"感
- 填错时：该格播放破碎动画，连击清零，所有持续特效立即消失，特效进度重新开始
- 特效不阻塞输入与游戏操作，不影响游戏逻辑判定

### FR-14 专家难度（第三轮需求新增）
- 新增第四档难度"专家"，难度高于"困难"
- 预填数少于困难（26-31），目标范围 22-25
- 专家谜题同样必须保证唯一解
- 难度选择菜单与游戏内难度标签同步支持"专家"

## Non-Functional Requirements

### NFR-1 架构约束
- 纯前端应用，无后端、无网络请求（除静态资源加载）

### NFR-2 技术栈
- Phaser 3（游戏引擎）+ TypeScript + Vite + npm

### NFR-3 浏览器兼容
- 支持现代桌面浏览器（Chrome / Edge / Firefox 最新两个大版本）

### NFR-4 性能
- 渲染流畅（目标 60 FPS），输入响应即时（< 100ms）
- 谜题生成不阻塞 UI 超过 1 秒

### NFR-5 界面与可用性
- 全中文界面
- 9x9 棋盘清晰可读，宫格（3x3）边界视觉区分
- 选中格及其关联行/列/宫高亮辅助

### NFR-6 持久化
- localStorage 容量内可靠存取存档；读取失败时优雅降级为新游戏

## Functional Requirements（第四轮新增）

### FR-15 游戏模式选择
- 开始游戏前，玩家先选择"线上游戏"或"本地游戏"
- 点击模式后界面滑动切换至第二屏进行难度选择（含"返回"按钮，实施期修订）
- 本地游戏与当前版本行为完全一致（含 localStorage 存档续玩）

### FR-16 后端对局服务
- 新增独立后端服务：Node.js + TypeScript + ws（WebSocket）
- 负责房间管理、对局状态权威存储、操作广播
- 无需注册/登录，连接即可玩

### FR-17 线上开局与匹配
- 玩家选择线上游戏后先选择难度（四档，同 FR-2/FR-14）
- 若系统中无可加入的已开始对局：自动创建新对局，玩家先单人进行（体验同本地游戏）
- 若系统中已有可加入的对局，按优先级匹配：① 相同难度中最早开始的对局；② 其他难度按档位距离升序、同距离**更难档优先**的对局中最早开始的一局（如选"中等"：困难 → 简单 → 专家；选"困难"：专家 → 中等 → 简单）；③ 均无可加入对局时创建新对局（Application Design 评审变更：原"随机选个难度最相近的"细化为该优先级规则）
- "可加入"定义：对局进行中且当前只有 1 名玩家

### FR-18 双人实时状态共享
- 同一对局中，双方实时看到对方的：填数（含对/错）、错填格、笔记
- 服务端为状态权威方，客户端操作经服务端确认后广播

### FR-19 新玩家加入提示
- 新玩家加入时，已在局玩家在界面右上方收到非阻塞提示（不弹窗、不中断操作）
- 不阻止新玩家加入

### FR-20 特效与视觉隔离
- 只有自己填对数字才触发本地连击特效（FR-13）
- 对方填对数字：本端仅显示该格被填入数字，不触发特效
- 归属着色：自己填入的正确数字用蓝色，对方填入为黑色；错填双方均标红

### FR-21 笔记共享与联动清除
- 双方笔记互相可见、互相可以修改
- 任一方填对数字后，双方相关行/列/宫笔记中的该数字同步清除（FR-6 规则扩展至双人）
- **【第五轮修订】本条由 FR-34 取代：笔记改为私有，联动清除由服务端代执行**

### FR-22 线上胜利判定（合作制）
- 棋盘填满且全部正确时，双方共同胜利，均看到胜利反馈与用时
- **【第五轮修订】本条由 FR-36 取代：合作共同胜利改为竞速比分胜负**

### FR-23 线上错误计数
- 错误次数各自独立计数（上限 3 次）
- 一方错满 3 次：仅该玩家判负并转为旁观（可看棋盘，不可操作），另一方继续完成对局
- **【第五轮修订】本条由 FR-37 取代：废除判负旁观，错误改为扣分**

### FR-24 线上计时器
- 共享计时：从房间创建起算，双方看到同一时钟；页面不可见时计时暂停规则（第三轮 Q3）不适用于线上共享时钟

### FR-25 线上撤销/重做与提示
- 撤销/重做仅回退自己的填数与笔记操作
- 提示功能在线上模式禁用

### FR-26 线上擦除权限
- 任何玩家可擦除任何错填的格子（不限于自己填的）
- **【第五轮修订】本条由 FR-35 取代：erase 仅限归属者；错填格改为任何人可 fill 覆盖**

### FR-27 线上对局控制限制
- 线上模式禁用"重开"与"新游戏"按钮
- 玩家可通过返回主菜单/关闭页面退出当前房间

### FR-28 断线与补位
- 玩家断线/关闭页面后，房间与其对局状态保留
- 空出的玩家位置可被后续新匹配的玩家顶替（FR-17 匹配逻辑持续生效）
- 新加入玩家从当前棋盘状态继续，其个人错误计数从 0 起算
- **【第五轮修订】本条由 FR-38 取代：双人成局后一方离开即判对方胜，不再补位**

### FR-29 本地模式回归约束
- 以上改动不得破坏本地模式的任何既有行为（FR-1~FR-14）

### FR-30 在线人数显示（第五轮新增）
- 线上对局的棋盘界面右上角持续显示当前房间在线人数（格式："在线 n/2"）
- 玩家加入（playerJoined）/离开（playerLeft）时即时更新；错满旁观者不离开房间，人数不变（**【第五轮修订】旁观机制废除，"错满旁观者"情形不再存在**）
- 仅线上模式显示；本地模式不出现（FR-29 约束）
- 显示为非交互元素，不遮挡棋盘操作

## 关键需求摘要（第四轮）

在既有纯前端数独游戏基础上新增多人能力：独立 WebSocket 后端（Node.js + TS + ws，内存态，局域网形态），免登录；开局前选择线上/本地模式，本地模式行为不变；线上按难度自动匹配（同难度最早优先，否则随机最相近），无局则自建先单人玩；双人实时共享填数/错填/笔记，笔记互相可改、填对联动清笔记；合作制共同胜利，错误各自计 3 次、错满者旁观；共享计时；撤销仅回退自己、提示禁用、重开/新游戏禁用；断线后空位可被新玩家顶替；特效仅自己填对触发，填数归属着色区分（自己蓝/对方黑）。

## Functional Requirements（第五轮新增/取代）

### FR-31 线上计分系统
- 每名玩家独立计分，服务端权威结算：fill 填对 +100；fill 填错 -100
- 分数下限为 0：扣分后低于 0 时 clamp 到 0
- 分数变化随 opApplied 广播实时同步给双方（对手分数可见）

### FR-32 连击计分
- 同一玩家连续填对构成连击计数；从第 3 次连续填对起，每次填对额外 +20（固定不递增）
- 连击清零条件：① 自己填错；② 自己 erase；③ 自己 undo；④ 自己 redo（**【Application Design 变更】原 ⑤"对方填对清零"已删除：连击为个人节奏奖励，对方操作不影响本玩家连击**）
- 连击计数为服务端状态，随分数同步（**【Application Design 修订（Q2 补充）】连击计数不下发、界面不显示，纯服务端内部状态；同步负载仅含双方总分**）

### FR-33 undo/erase 分数结算（防刷分）
- undo 自己的正确填入：-100（返还得分，受 FR-31 下限 0 clamp）；redo 自己的正确填入：+100（对称恢复）
- undo/redo 错填：分数不变（错填 -100 一经结算永久生效，不返还不重复扣）
- erase 自己的正确格：-100（ clamp 到 0）；erase 错填格（自己的）：分数不变
- 覆盖对方错填格填对：覆盖者正常 +100；原错填者的 -100 不退还

### FR-34 笔记私有化（取代 FR-21）
- 笔记按玩家私有存储，仅同步给归属者；对方玩家不可见、不可修改
- 任一方填对数字后，服务端代清双方相关行/列/宫私有笔记中的该值（双方各自只看到自己笔记被清）
- 笔记相关的 opApplied 广播不得向对方泄露笔记内容

### FR-35 线上操作权限（取代 FR-26，修订 BR-S-21 语义）
- fill：目标格须为空格、归属者为自己的格、或任何 wrong=true 的错填格；覆盖对方**正确**格 → 拒绝
- 覆盖错填格成功（无论对错）后，该格归属者转移为操作发起者
- erase：仅限归属者擦除自己的格（正确格或错填格均可）；任何非归属格 → 拒绝
- undo/redo 仍仅限自己的操作记录（BR-S-10 语义保留），分数结算按 FR-33

### FR-36 线上胜负判定（竞速制，取代 FR-22）
- 棋盘填满且全部正确时终局：分数高者胜，平分判平局
- 双人成局后（房间曾有 2 名玩家），任一方离开/断线：在局玩家直接判胜，房间进入终局
- 终局广播携带双方最终分数与胜负结果

### FR-37 判负旁观机制废除（取代 FR-23）
- 移除错误次数上限与错满判负旁观；移除 playerLost 广播

## 关键需求摘要（第五轮）

线上模式由合作制改为竞速对抗制：双方在同一棋盘抢填，填对 +100、填错 -100（下限 0），连续填对第 3 次起每次 +20；连击仅被自己填错/erase/undo/redo 清零（不受对方操作影响）；undo 正确填入返还 -100、错填扣分永久不返还（防穷举）；笔记私有化、服务端代清联动；正确格仅归属者可动、错填格任何人可覆盖（防占位）、erase 仅归属者；废除错 3 次判负旁观；棋盘填满比分定胜负（平分判和）；对手中途离开直接判胜；终局仅展示双方分数与胜负。本地模式行为完全不变。

## Intent Analysis Summary（第三轮 - 专家难度）

## Intent Analysis Summary（第二轮 - 连击特效）

- **User Request**: "我希望每填对一个数字的时候，填对的那个格子来点特效。当连续填对的时候，特效会越来越华丽越来越夸张。比如填对一整行或一整列或者一个9宫格的数字时，有个整行整列或者9宫格的特效。与此同时，如果还连续填对，特效逐步从一个格子逐步扩张到整个屏幕都有特效。同时棋盘逐步有个持续的特效，让气氛热起来。反正就是不停地给正面刺激。当过程中有个格子填错时，有个破碎的动画，持续的特效也消失不见，一切特效重新开始。"
- **Request Type**: New Feature（既有项目的功能增强）
- **Scope Estimate**: Single component（表现层新增 VFX 组件 + GameScene/GameController 接线）
- **Complexity Estimate**: Simple（纯表现层，无游戏逻辑变更；唯一核心改动为 inputDigit 返回判定结果）
- **Requirements Depth**: Minimal（需求描述具体完整，无歧义，无需澄清问题）
