# Requirements - 数独 Web 游戏

## Intent Analysis Summary

- **User Request**: "我想创建一个可以玩数独的web游戏，只有前端，没有后端。前端使用游戏引擎。"
- **Request Type**: New Project (greenfield)
- **Scope Estimate**: Single application（单前端应用）
- **Complexity Estimate**: Simple-to-Moderate
- **Requirements Depth**: Standard

## 需求决策（来自澄清问题）

| 决策项 | 选择 |
|---|---|
| 游戏引擎 | Phaser 3 |
| 开发语言 | TypeScript |
| 构建工具 | Vite + npm |
| 功能范围 | 完整版 |
| 界面语言 | 中文 |

## Functional Requirements

### FR-1 谜题生成
- 随机生成数独谜题，保证有唯一解
- 生成过程在客户端完成，无网络依赖

### FR-2 难度选择
- 提供三档难度：简单 / 中等 / 困难（第三轮 FR-14 扩展为四档，新增"专家"）
- 不同难度对应不同的预填数字数量（挖空数量不同）

### FR-3 数字填写
- 点击选中格子后输入数字
- 支持屏幕数字键盘（点击）和物理键盘（1-9）两种输入方式
- 预填格子（题目给定）不可修改，视觉上与用户填写数字区分

### FR-4 冲突提示
- 输入与同行、同列或同宫已有数字冲突时，立即给出视觉提示（高亮冲突格）

### FR-5 完成判定
- 棋盘填满且全部正确时判定胜利，展示胜利反馈与用时

### FR-6 候选数笔记
- 支持笔记模式（pencil marks）：在格子内标注多个候选数
- 笔记模式与正式填写模式可切换
- 正式填入数字后自动清除同行/列/宫中相同的候选数标注

### FR-7 计时器
- 游戏开始后自动计时并显示
- 胜利后停止计时

### FR-8 提示功能
- 玩家可请求提示，系统自动填入一个正确的空格数字

### FR-9 错误次数限制
- 填入错误数字计入错误次数
- 错误次数达到上限（3 次）判定失败，展示失败反馈

### FR-10 撤销 / 重做
- 支持撤销上一步操作（填数、删数、笔记）与重做

### FR-11 本地存档
- 使用 localStorage 自动保存游戏进度（棋盘状态、难度、用时、错误次数、操作历史）
- 重新打开页面时可选择继续上次游戏或开始新游戏

### FR-12 新游戏 / 重开
- 可随时开始新游戏（选择难度）
- 可重置当前谜题重新开始

### FR-13 连击特效系统（第二轮需求新增）- 填对一个数字时，该格子播放正面反馈特效（粒子爆发等）
- 连击机制：连续填对时特效分档升级，从单格特效逐步扩张到全屏特效
- 完成整行/整列/整宫（9 格全部填对）时，触发该区域的整体特效
- 高档连击伴随棋盘持续氛围特效（如边框脉冲、上升粒子），营造"热场"感
- 填错时：该格播放破碎动画，连击清零，所有持续特效立即消失，特效进度重新开始
- 特效不阻塞输入与游戏操作，不影响游戏逻辑判定

### FR-14 专家难度（第三轮需求新增）
- 新增第四档难度"专家"，难度高于"困难"
- 预填数少于困难（26-31），目标范围 22-25
- 专家谜题同样必须保证唯一解
- 难度选择菜单与游戏内难度标签同步支持"专家"

## Non-Functional Requirements

### NFR-1 架构约束
- 纯前端应用，无后端、无网络请求（除静态资源加载）

### NFR-2 技术栈
- Phaser 3（游戏引擎）+ TypeScript + Vite + npm

### NFR-3 浏览器兼容
- 支持现代桌面浏览器（Chrome / Edge / Firefox 最新两个大版本）

### NFR-4 性能
- 渲染流畅（目标 60 FPS），输入响应即时（< 100ms）
- 谜题生成不阻塞 UI 超过 1 秒

### NFR-5 界面与可用性
- 全中文界面
- 9x9 棋盘清晰可读，宫格（3x3）边界视觉区分
- 选中格及其关联行/列/宫高亮辅助

### NFR-6 持久化
- localStorage 容量内可靠存取存档；读取失败时优雅降级为新游戏

## Functional Requirements（第四轮新增）

### FR-15 游戏模式选择
- 开始游戏前，玩家先选择"线上游戏"或"本地游戏"
- 本地游戏与当前版本行为完全一致（含 localStorage 存档续玩）

### FR-16 后端对局服务
- 新增独立后端服务：Node.js + TypeScript + ws（WebSocket）
- 负责房间管理、对局状态权威存储、操作广播
- 无需注册/登录，连接即可玩

### FR-17 线上开局与匹配
- 玩家选择线上游戏后先选择难度（四档，同 FR-2/FR-14）
- 若系统中无可加入的已开始对局：自动创建新对局，玩家先单人进行（体验同本地游戏）
- 若系统中已有可加入的对局，按优先级匹配：① 相同难度中最早开始的对局；② 其他难度按档位距离升序、同距离**更难档优先**的对局中最早开始的一局（如选"中等"：困难 → 简单 → 专家；选"困难"：专家 → 中等 → 简单）；③ 均无可加入对局时创建新对局（Application Design 评审变更：原"随机选个难度最相近的"细化为该优先级规则）
- "可加入"定义：对局进行中且当前只有 1 名玩家

### FR-18 双人实时状态共享
- 同一对局中，双方实时看到对方的：填数（含对/错）、错填格、笔记
- 服务端为状态权威方，客户端操作经服务端确认后广播

### FR-19 新玩家加入提示
- 新玩家加入时，已在局玩家在界面右上方收到非阻塞提示（不弹窗、不中断操作）
- 不阻止新玩家加入

### FR-20 特效与视觉隔离
- 只有自己填对数字才触发本地连击特效（FR-13）
- 对方填对数字：本端仅显示该格被填入数字，不触发特效
- 对方填入的正确数字用蓝色区分（本地填写为黑色）；错填双方均标红

### FR-21 笔记共享与联动清除
- 双方笔记互相可见、互相可以修改
- 任一方填对数字后，双方相关行/列/宫笔记中的该数字同步清除（FR-6 规则扩展至双人）

### FR-22 线上胜利判定（合作制）
- 棋盘填满且全部正确时，双方共同胜利，均看到胜利反馈与用时

### FR-23 线上错误计数
- 错误次数各自独立计数（上限 3 次）
- 一方错满 3 次：仅该玩家判负并转为旁观（可看棋盘，不可操作），另一方继续完成对局

### FR-24 线上计时器
- 共享计时：从房间创建起算，双方看到同一时钟；页面不可见时计时暂停规则（第三轮 Q3）不适用于线上共享时钟

### FR-25 线上撤销/重做与提示
- 撤销/重做仅回退自己的填数与笔记操作
- 提示功能在线上模式禁用

### FR-26 线上擦除权限
- 任何玩家可擦除任何错填的格子（不限于自己填的）

### FR-27 线上对局控制限制
- 线上模式禁用"重开"与"新游戏"按钮
- 玩家可通过返回主菜单/关闭页面退出当前房间

### FR-28 断线与补位
- 玩家断线/关闭页面后，房间与其对局状态保留
- 空出的玩家位置可被后续新匹配的玩家顶替（FR-17 匹配逻辑持续生效）
- 新加入玩家从当前棋盘状态继续，其个人错误计数从 0 起算

### FR-29 本地模式回归约束
- 以上改动不得破坏本地模式的任何既有行为（FR-1~FR-14）

## Non-Functional Requirements（第四轮新增）

### NFR-7 后端技术约束
- Node.js + TypeScript + 原生 ws 库；对局状态纯内存存储
- 运行形态：本机开发 + 局域网可访问

### NFR-8 实时性
- 局域网内操作同步延迟目标 < 200ms（操作发起到对端渲染）

### NFR-9 测试约束（PBT 扩展已启用）
- 新增属性测试框架 fast-check（与 Vitest 集成）
- 适用于：消息序列化/反序列化往返、匹配算法不变量、服务端对局状态机等（详见 PBT-01 分析）

### NFR-1 修订（DOC-01 同步）
- 原文"纯前端应用，无后端、无网络请求"自第四轮起仅适用于**本地游戏模式**；线上模式依赖 WebSocket 后端

## 关键需求摘要（第四轮）

在既有纯前端数独游戏基础上新增多人能力：独立 WebSocket 后端（Node.js + TS + ws，内存态，局域网形态），免登录；开局前选择线上/本地模式，本地模式行为不变；线上按难度自动匹配（同难度最早优先，否则随机最相近），无局则自建先单人玩；双人实时共享填数/错填/笔记，笔记互相可改、填对联动清笔记；合作制共同胜利，错误各自计 3 次、错满者旁观；共享计时；撤销仅回退自己、提示禁用、重开/新游戏禁用；断线后空位可被新玩家顶替；特效仅自己填对触发，对方填数蓝色区分。

## Intent Analysis Summary（第三轮 - 专家难度）

- **User Request**: "我想增加一个难度：专家。难度应该比困难还要难"
- **Request Type**: New Feature（既有功能扩展）
- **Scope Estimate**: Small（Difficulty 联合类型 + 生成器预填数范围 + 菜单/标签 + 测试）
- **Complexity Estimate**: Simple（唯一要点：预填数减少后唯一解生成耗时增加，需验证生成器稳定性）
- **Requirements Depth**: Minimal（需求明确，无歧义，无需澄清问题）

## Intent Analysis Summary（第二轮 - 连击特效）

- **User Request**: "我希望每填对一个数字的时候，填对的那个格子来点特效。当连续填对的时候，特效会越来越华丽越来越夸张。比如填对一整行或一整列或者一个9宫格的数字时，有个整行整列或者9宫格的特效。与此同时，如果还连续填对，特效逐步从一个格子逐步扩张到整个屏幕都有特效。同时棋盘逐步有个持续的特效，让气氛热起来。反正就是不停地给正面刺激。当过程中有个格子填错时，有个破碎的动画，持续的特效也消失不见，一切特效重新开始。"
- **Request Type**: New Feature（既有项目的功能增强）
- **Scope Estimate**: Single component（表现层新增 VFX 组件 + GameScene/GameController 接线）
- **Complexity Estimate**: Simple（纯表现层，无游戏逻辑变更；唯一核心改动为 inputDigit 返回判定结果）
- **Requirements Depth**: Minimal（需求描述具体完整，无歧义，无需澄清问题）

## 关键需求摘要（第一轮）

一个纯前端的中文数独 Web 游戏，基于 Phaser 3 + TypeScript + Vite 构建，功能为完整版：唯一解谜题生成、四档难度（含第三轮新增的专家档）、双输入方式、冲突提示、候选数笔记、计时、提示、错误限制（3 次）、撤销/重做、localStorage 存档续玩；第二轮新增连击特效系统。
