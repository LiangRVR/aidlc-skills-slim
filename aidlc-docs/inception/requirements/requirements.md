# 扫雷游戏需求文档

## 意图分析摘要

- **用户请求**: "我想开发一个类似于早期windows系统自带游戏的那种扫雷小游戏。"
- **请求类型**: New Project（全新开发；重建 `minesweeper/` 目录下源代码已丢失的旧项目）
- **范围估算**: Single Component（单一桌面应用）
- **复杂度估算**: Simple ~ Moderate（规则成熟明确，UI 交互有若干细节）

## 技术栈决策

| 项 | 决策 |
|---|---|
| 语言 / 运行时 | Python 3.13（沿用现有 `.venv` 的 cpython-313） |
| GUI 框架 | PySide6 + PySide6-Fluent-Widgets（QFluentWidgets，现代 Fluent 风格 UI；实现对齐 PySide6 生态，替代 PyQt5 系的 PyQt-Fluent-Widgets） |
| 包管理 / 构建 | uv |
| 单元测试 | pytest |
| 基于属性的测试（部分启用） | Hypothesis（PBT-02/03/07/08/09 为阻断约束，其余为建议性） |
| 打包 | PyInstaller（onefile，无控制台窗口，含图标） |

## 功能需求

### FR-1 棋盘与布雷
- FR-1.1 矩形网格棋盘，每格可处于：未打开 / 已打开 / 旗帜 / 问号 状态
- FR-1.2 按难度参数（行数 x 列数 x 雷数）随机布雷
- FR-1.3 **首次点击安全**：第一次点击时布雷，保证首点格子及其周围 8 格均不为雷

### FR-2 基本交互
- FR-2.1 左键打开格子；若周围雷数为 0，自动级联展开（flood fill）
- FR-2.2 右键标记循环：空白 → 旗帜 → 问号 → 空白
- FR-2.3 Chord 快速开格：在已打开的数字格上双击（或左右键同按），若周围旗帜数等于该格数字，自动打开其余未标记格子；旗数不足时高亮提示不动作
- FR-2.4 踩雷即输：显示全部雷位置，错误标记的旗帜以红叉标示
- FR-2.5 打开全部非雷格即胜：剩余雷自动标记为旗帜

### FR-3 难度
- FR-3.1 经典三档：初级 9x9/10 雷；中级 16x16/40 雷；高级 30x16/99 雷
- FR-3.2 自定义难度：用户输入行数、列数、雷数（雷数 < 行 x 列 - 9，保证首点安全可行）

### FR-4 游戏面板
- FR-4.1 剩余雷数计数器（总雷数 - 旗帜数，可为负数）
- FR-4.2 计时器：首次点击开始计时，胜负已定后停止，上限 999 秒
- FR-4.3 笑脸按钮：正常 😊 / 按下 😮 / 胜利 😎 / 失败 😵，点击重新开始当前难度
- FR-4.4 通关画面：胜利时弹出恭喜对话框（显示扫雷数与用时），可"再来一局"（同难度重开）或"关闭"；一局仅弹出一次（变更请求 2026-09-04）

## 非功能需求

- NFR-1 单机本地应用，无网络依赖，无敏感数据处理
- NFR-2 高级难度（480 格）下级联展开不得有可感知卡顿（< 100ms）
- NFR-3 核心游戏逻辑与 UI 分离：逻辑层为纯 Python，不依赖 Qt，便于测试
- NFR-4 测试：核心逻辑（布雷、邻雷计数、展开、chord、胜负判定）需 pytest 单元测试 + Hypothesis 属性测试（部分 PBT 模式）
- NFR-5 交付物：可通过 `uv run` 从源码运行，并提供 PyInstaller 打包的 Windows exe

## 关键需求摘要

复刻经典 Windows 扫雷的核心玩法与交互（首点安全、级联展开、旗/问号标记、chord、计数器/计时器/笑脸），采用 PySide6 + QFluentWidgets 现代 UI，uv 管理依赖，pytest + Hypothesis（部分）测试，PyInstaller 打包 exe。
