# 错误处理与恢复流程

## 通用错误处理原则

### 当错误发生时
1. **识别错误**：清楚地说明出了什么问题
2. **评估影响**：确定错误是阻塞性的还是可以绕过的
3. **沟通**：告知用户错误及可选项
4. **提供解决方案**：给出解决或绕过错误的清晰步骤
5. **记录**：在 `audit.md` 中记录错误和解决方案

### 错误严重级别

**严重**：工作流无法继续
- 缺少必需文件或制品
- 无法处理的无效用户输入
- 阻止文件操作的系统错误

**高**：子阶段无法按计划完成
- 必需问题回答不完整
- 相互矛盾的用户响应
- 缺少先前子阶段的依赖

**中**：子阶段可以通过变通方案继续
- 缺少可选制品
- 非关键验证失败
- 可以部分完成

**低**：不阻塞进度的小问题
- 格式不一致
- 缺少可选信息
- 非阻塞性警告

## 特定子阶段的错误处理

### 工作区检测错误

**错误**：无法读取工作区文件
- **原因**：权限问题、目录缺失
- **解决方案**：请用户验证工作区路径和权限
- **变通方案**：仅使用用户提供的信息继续

**错误**：现有的 `aidlc-state.md` 已损坏
- **原因**：手动编辑、上一次运行未完成
- **解决方案**：询问用户是希望重新开始还是尝试恢复
- **恢复**：创建备份，启动新的状态文件

**错误**：无法确定所需子阶段
- **原因**：用户提供的信息不足
- **解决方案**：询问关于意图和范围的澄清问题
- **变通方案**：默认采用全面执行计划

### 需求分析错误

**错误**：用户提供相互矛盾的需求
- **原因**：理解不清、需求在变化
- **解决方案**：创建后续问题以解决矛盾
- **不要继续**：直到矛盾解决

**错误**：无法转换需求文档
- **原因**：不支持的格式、文件损坏
- **解决方案**：请用户以支持的格式提供需求
- **变通方案**：基于用户的口头描述进行

**错误**：验证问题回答不完整
- **原因**：用户跳过了问题，不清楚要回答什么
- **解决方案**：突出未回答的问题，提供示例
- **不要继续**：直到所有必需问题都得到回答

### 用户故事错误

**错误**：无法将需求映射到故事
- **原因**：需求过于模糊、缺少功能细节
- **解决方案**：返回需求分析以获取澄清
- **变通方案**：基于可用信息创建故事，标记为不完整

**错误**：用户提供模糊的故事规划答案
- **原因**：选项不清、决策复杂
- **解决方案**：添加带具体示例的后续问题
- **不要继续**：直到歧义解决

**错误**：故事生成计划有未完成步骤
- **原因**：执行被中断、步骤被跳过
- **解决方案**：从第一个未完成步骤继续
- **恢复**：审查已完成步骤，从检查点继续

### 应用设计错误

**错误**：架构决策不清晰或相互矛盾
- **原因**：答案含糊、需求冲突
- **解决方案**：添加后续问题以澄清决策
- **不要继续**：直到决策清晰并记录在案

**错误**：无法确定服务/工作单元数量
- **原因**：关于边界的信息不足
- **解决方案**：询问关于部署、团队结构、扩展的具体问题
- **变通方案**：默认单体架构，允许稍后更改

### 设计错误

**错误**：工作单元依赖是循环的
- **原因**：边界定义不佳、耦合紧密
- **解决方案**：识别循环依赖，建议重构
- **恢复**：修订工作单元边界以打破循环

**错误**：工作单元设计计划缺少步骤
- **原因**：计划生成不完整、模板错误
- **解决方案**：用所有必需步骤重新生成计划
- **恢复**：在现有计划中添加缺失步骤

**错误**：无法生成设计制品
- **原因**：缺少工作单元信息、需求不清
- **解决方案**：返回工作单元生成以澄清单元定义
- **变通方案**：生成部分设计，标记缺口

### NFR 实施错误

**错误**：技术栈选择不兼容
- **原因**：需求冲突、平台限制
- **解决方案**：突出不兼容之处，请用户选择
- **不要继续**：直到做出兼容的选择

**错误**：无法满足组织约束
- **原因**：网络限制、安全策略
- **解决方案**：记录约束，请用户提供变通方案
- **升级**：可能需要人工干预进行设置

**错误**：NFR 实施步骤需要人工操作
- **原因**：AI 无法执行某些任务（网络配置、凭据）
- **解决方案**：明确标记为 **HUMAN TASK**，提供说明
- **等待**：继续前进前等待用户确认

### 代码生成规划错误

**错误**：代码生成计划不完整
- **原因**：缺少设计制品、需求不清
- **解决方案**：返回设计子阶段以完成制品
- **恢复**：使用可用信息生成计划，标记缺口

**错误**：工作单元依赖未满足
- **原因**：依赖的工作单元尚未生成
- **解决方案**：重新排序生成顺序以遵守依赖关系
- **变通方案**：使用桩依赖生成，稍后集成

### 代码生成错误（第 2 部分：代码生成）

**错误**：无法为某个步骤生成代码
- **原因**：设计信息不足、需求不清
- **解决方案**：跳过步骤，记录为不完整，继续
- **恢复**：收集更多信息后返回该步骤

**错误**：生成的代码有语法错误
- **原因**：模板问题、语言特定问题
- **解决方案**：修复语法错误，必要时重新生成
- **验证**：继续前验证代码可编译

**错误**：测试生成失败
- **原因**：逻辑复杂、缺少测试框架设置
- **解决方案**：生成基本测试结构，标记为手动完成
- **变通方案**：在没有测试的情况下继续，在 Operations 阶段添加

### Operations 错误

**错误**：无法确定构建工具
- **原因**：项目结构异常、存在多个构建系统
- **解决方案**：请用户指定构建工具和命令
- **变通方案**：提供通用说明，由用户调整

**错误**：部署目标不明确
- **原因**：多环境、基础设施复杂
- **解决方案**：请用户指定部署目标和方法
- **变通方案**：为常见平台提供说明

## 恢复流程

### 部分子阶段完成

**场景**：子阶段执行中途被中断

**恢复步骤**：
1. 加载子阶段计划文件
2. 识别最后完成的步骤（最后一个 [x] 复选框）
3. 从下一个未完成步骤继续
4. 验证所有先前步骤确实完成
5. 正常继续执行

### 状态文件损坏

**场景**：`aidlc-state.md` 已损坏或不一致

**恢复步骤**：
1. 创建备份：`aidlc-state.md.backup`
2. 询问用户他们实际处于哪个子阶段
3. 从头重新生成状态文件
4. 根据现有制品标记已完成的子阶段
5. 从当前子阶段继续

### 制品缺失

**场景**：来自先前子阶段的必需制品缺失

**恢复步骤**：
1. 识别哪些制品缺失
2. 确定它们是否可以重新生成
3. 如果可以：返回该子阶段，重新生成制品
4. 如果不可以：请用户手动提供信息
5. 在 `audit.md` 中记录该缺口

### 用户希望重启子阶段

**场景**：用户对子阶段结果不满意，希望重做

**恢复步骤**：
1. 确认用户要重启（数据将丢失）
2. 归档现有制品：`{artifact}.backup`
3. 在 `aidlc-state.md` 中重置子阶段状态
4. 清除计划文件中的子阶段复选框
5. 从头重新执行子阶段

### 用户希望跳过子阶段

**场景**：用户希望跳过已规划的子阶段

**恢复步骤**：
1. 确认用户理解影响
2. 在 `audit.md` 中记录跳过原因
3. 在 `aidlc-state.md` 中将子阶段标记为"已跳过"
4. 进入下一子阶段
5. 注意：如果缺少依赖，可能会在后续子阶段引起问题

## 升级指南

### 何时寻求用户帮助

**立即**：
- 相互矛盾或模糊的用户输入
- 缺少必需信息
- AI 无法解决的技术约束
- 需要业务判断的决策

**尝试解决之后**：
- 同一步骤反复出错
- 复杂的技术问题
- 异常的项目结构
- 与外部系统的集成

### 何时建议重新开始

**如果出现以下情况，考虑全新开始**：
- 多个子阶段都有错误
- 状态文件严重损坏
- 用户需求发生重大变化
- 需要推翻架构决策
- 用户无法提供缺失信息
- 各阶段制品不一致

**重新开始之前**：
1. 归档所有现有工作
2. 记录经验教训
3. 确定要保留的内容
4. 获得用户确认
5. 创建新的执行计划

## 会话恢复错误

### 恢复期间制品缺失

**错误**：来自先前子阶段的必需制品缺失
- **原因**：文件被删除、移动或从未创建
- **解决方案**：
  1. 识别哪个子阶段创建了缺失的制品
  2. 检查该子阶段在 aidlc-state.md 中是否被标记为完成
  3. 如果标记为完成但制品缺失：重新生成该子阶段
  4. 如果未标记为完成：从该子阶段继续
- **恢复**：返回创建缺失制品的子阶段并重新执行

**错误**：制品文件存在但为空或已损坏
- **原因**：写入中断、手动编辑、文件系统问题
- **解决方案**：
  1. 创建损坏文件的备份
  2. 尝试从创建它的子阶段重新生成
  3. 如果无法重新生成：请用户提供信息以重新创建
- **恢复**：重新执行创建该制品的子阶段

### 恢复期间状态不一致

**错误**：aidlc-state.md 显示子阶段完成但制品不存在
- **原因**：状态文件已更新但制品生成失败
- **解决方案**：
  1. 在 aidlc-state.md 中将子阶段标记为未完成
  2. 重新执行该子阶段以生成制品
  3. 在标记完成前验证制品存在
- **恢复**：重置子阶段状态并重新执行

**错误**：制品存在但 aidlc-state.md 显示子阶段未完成
- **原因**：制品生成成功但状态更新失败
- **解决方案**：
  1. 验证制品完整且有效
  2. 更新 aidlc-state.md 将子阶段标记为完成
  3. 进入下一子阶段
- **恢复**：更新状态文件以反映实际完成情况

**错误**：aidlc-state.md 中多个子阶段被标记为"当前"
- **原因**：状态文件损坏、手动编辑
- **解决方案**：
  1. 审查制品以确定实际进度
  2. 询问用户他们实际处于哪个子阶段
  3. 修正 aidlc-state.md 以显示单一当前子阶段
- **恢复**：基于现有制品重建状态文件

### 上下文加载错误

**错误**：无法从先前子阶段加载所需上下文
- **原因**：文件缺失、内容损坏、文件路径错误
- **解决方案**：
  1. 列出当前子阶段所需的制品
  2. 检查哪些缺失或损坏
  3. 重新生成缺失制品或请用户提供信息
- **恢复**：在恢复当前子阶段之前完成前置子阶段

**错误**：加载的制品包含相互矛盾的信息
- **原因**：手动编辑、多人协作、更新不完整
- **解决方案**：
  1. 识别矛盾并向用户呈现
  2. 询问用户哪个信息是正确的
  3. 更新制品以解决矛盾
- **恢复**：在继续前协调矛盾

### 恢复最佳实践

1. **始终验证状态**：检查 aidlc-state.md 是否与实际制品一致
2. **增量加载**：逐子阶段加载制品，逐个验证
3. **快速失败**：如果关键制品缺失，立即停止
4. **清晰沟通**：准确告知用户缺失了什么以及为什么需要
5. **提供选项**：重新生成、手动提供或重新开始
6. **记录恢复**：在 audit.md 中记录所有恢复操作

## 日志记录要求

### 错误日志格式

```markdown
## Error - [Stage Name]
**Timestamp**: [ISO timestamp]
**Error Type**: [Critical/High/Medium/Low]
**Description**: [What went wrong]
**Cause**: [Why it happened]
**Resolution**: [How it was resolved]
**Impact**: [Effect on workflow]

---
```

### 恢复日志格式

```markdown
## Recovery - [Stage Name]
**Timestamp**: [ISO timestamp]
**Issue**: [What needed recovery]
**Recovery Steps**: [What was done]
**Outcome**: [Result of recovery]
**Artifacts Affected**: [List of files]

---
```

## 预防最佳实践

1. **尽早验证**：在开始工作前检查输入和依赖
2. **经常设置检查点**：完成步骤后立即更新复选框
3. **清晰沟通**：解释你在做什么以及为什么
4. **提出问题**：不要假设——立即澄清歧义
5. **记录一切**：在 `audit.md` 中记录所有决策和变更
